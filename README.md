你在 console.anthropic.com 的账单页翻了一圈，发现收银台只有卡号、有效期、CVV 那套表单，没有扫码，也没有"微信支付"四个字。这不是页面没刷新，也不是你账号级别不够。往下看，这件事能解释清楚，也有几条真的能走通的路。

## 先把官方那套计费机制弄清楚

Claude API 不是订阅制，是预付额度制。流程只有在账单页才有：进 Settings → Billing，绑定一张卡，然后买额度。之后每调一次模型按 token 扣，余额见底时可以开自动续充，设一个阈值，比如余额低于某个数就自动补钱。这个开关在生产环境里比什么都重要，余额跑空导致接口突然 401 是很常见的事故。

额度买多少，跟你的用量档位挂钩。Anthropic 的用量层级跟着累计购买金额往上走，买得越多，速率上限越高，这对跑批处理或者高频调用的项目影响不小。

有个细节容易被忽略：官方条款给预付额度设了有效期，撰写时是 12 个月。所以别一上来充一年的量，用不完就浪费了。具体期限请以官方条款最新版本为准。

## 官方为什么接不了微信和支付宝

问题不在支付方式，而在地区。Anthropic 只在它公布的支持国家和地区清单里卖 API，中国大陆不在这个名单上。这意味着两件事：

第一，国内银行发行的外币卡，在官方收银台被拒是常态，原因不一定是余额，更多是发卡行和账单地址的匹配问题。

第二，用 VPN 把位置伪装成支持地区，本身违反服务条款，账号被标记的风险由你自己承担。

渠道层面还有一笔隐性成本。虚拟信用卡开卡要钱，充值有手续费，被风控冻结的余额往往拿不回来。你在论坛里能看到不少人抱怨"卡里还有钱，但付不了了"。折腾一圈下来，省下的汇率差可能还不够填这些坑。

## 人民币把额度充进去的几条路径

### 路径一：官方直连 + 自己搞定海外卡

前提是有稳定可用的境外卡、账单地址能对上、IP 环境干净。满足这些条件，这是成本最低、最省事的方式，没有中间商抽成，也没有额度二次转手的损耗。不满足的话，这条路就是持续消耗精力。

### 路径二：API 聚合平台 / 中转站

这类平台的逻辑是：它用企业渠道跟上游对接，你拿到一把 API Key，改一行 `base_url` 就能调。接口大多兼容 OpenAI 格式，也有的同时支持 Anthropic 原生格式，tool use、streaming 这些能力不受影响。

计费上普遍用"倍率"这个概念，实际成本 = 官方价 × 倍率。倍率低于 1 意味着比官方便宜，高于 1 通常是因为上游供给紧张。这里要留个心眼：便宜到离谱的倍率不一定可信，业内确实存在"模型掺水"的情况——你以为调的是高端模型，返回的其实是低一档的响应。判断方式也简单，小额跑一段时间真实业务，看高峰期延迟、失败率和账单。

支付通道本身也不稳定。有平台就公开更正过自己的文档：早期支持微信支付，后来微信通道撤了，人民币充值改成走支付宝。所以"支持微信"这件事在 API 充值这个场景里，需要你自己在下单页确认一遍。

## 充值前后要注意的几件事

- **别一次充太多。** 官方额度有有效期，第三方平台的余额规则各家不同，按需充是对自己最友好的做法。
- **核对倍率和缓存计费。** 缓存读写在不同平台的价格差异很大，有的平台缓存价格是常规价的几倍，而另一些平台只有零点几倍。大量用 Prompt Caching 的项目，账单差距会很明显。
- **敏感数据做脱敏。** 不管走官方还是中转，涉及用户隐私和商业机密的内容都别原样塞进 prompt。
- **定期对用量面板。** token 消耗突然飙高，往往是代码里有个循环在反复重试。
- **账号归属想清楚。** 用自己的账号订阅，你保留控制权；平台代注册的账号，你得接受它的规则边界。

## 常见问题

**Claude API 官方支持微信支付吗？**
不支持。官方收银台只接受国际信用卡和绑定外币卡的 PayPal，且中国大陆不在 API 支持地区清单内。

**那能不能用微信给 Claude Pro 充值？**
可以，但走的是第三方代付平台，不是 Anthropic 官方。付款用微信或支付宝，实际开通由平台完成。你的 Claude 账号本身不变。

**中转平台便宜这么多，会不会有问题？**
倍率低不等于一定掺水，优质平台靠批量采购和自建号池压低上游成本。但价格低到明显不合理时，先用小额真实业务验证输出质量再加大投入。

**充值进去的额度能退吗？**
官方预付额度一般不退，这也是不建议一次充大额的原因。第三方平台各有各的退款条款，代付失败通常会退，封号之类的情况各家规则差别很大，下单前问客服。

**Claude Code 走订阅还是走 API 更划算？**
日常写代码、固定时间使用，订阅的额度更划算。跑自动化任务、调用量波动大、要把 Claude 嵌进自己的服务里，按量付费更合适。两者计费体系独立，额度不通用。
